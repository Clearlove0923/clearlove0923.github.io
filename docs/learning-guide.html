一、项目现在做什么

SteamCN-GameLauncher 是一个 WinUI 3 桌面应用，用来管理已经安装在本地的国服游戏。它既能生成 Steam 所需的 ACF 安装记录，也能按每款游戏保存的模式直接启动国服、通过 Steam 启动国服，或沿用 Steam 国际服启动路径。

  • 游戏配置：AppID、Depot、Manifest、占位 EXE、真实 EXE、工作目录与启动参数。
  • 游戏首页：官方背景、海报、轮播和资讯，带内存、磁盘与媒体缓存。
  • 运行记录：真实进程级时长统计、趋势图与年度热力图。
  • 截图：按游戏保存目录，按日期浏览、预览、定位或移入回收站。
  • 软件更新：CNB / GitHub 双源，更新说明、下载进度与完整性校验。

二、v3.1.6 架构

层主要文件与职责
应用外壳Program.cs、App.xaml.cs、MainWindow*.cs：进程入口、导航、外观与托盘生命周期。
页面Views/Pages：首页、配置、启动测试、时长、截图、外观与设置界面。
配置与 SteamSteamService、SteamAppInfoService、ManifestFileService、CustomManifestService：路径检测、元数据、ACF 生成与安全备份。
启动DirectGameLaunchService 与 SteamLaunchService：根据每款游戏保存的模式执行真实启动链。
首页内容Services/Home：内容传输、缓存、媒体优化、背景切换与内置 Python Worker 生命周期。
数据 Providerpython/home_content：按厂商和游戏来源获取官方内容，并转换为统一 HomeContent 模型。
个人记录PlayTimeService、GameTimeStorage、ScreenshotCatalogService：时长会话与截图目录管理。
软件更新Services/Update 与 UpdateService：来源策略、CNB 完整包、SHA-256 校验和 Kachina 更新界面。

三、主要调用链

保存游戏配置

配置页面
  → SteamAppInfoService 获取公开元数据
  → SteamAppSelectionService 处理候选
  → CustomManifestService 生成配置
  → ManifestFileService 备份并原子写入 ACF

启动游戏

首页选择启动方式
  ├─ 国服 → DirectGameLaunchService → 真实游戏 EXE
  ├─ Steam 玩国服 → SteamLaunchService → AppID + 国服启动选项
  └─ Steam 玩国际服 → SteamLaunchService → Steam 原始启动路径
       → PlayTimeService 跟踪真实游戏进程

加载首页内容

LauncherHomePage
  → CachedHomeContentService 先返回可用缓存
  → FastApiHomeContentService 请求本机 Worker
  → Provider Registry 选择厂商来源
  → 官方站点 / 本地启动器资源
  → 媒体缓存与兼容性处理
  → HomeBackdropCoordinator 更新首页背景

四、开发环境

  • Windows 10 / 11 x64。
  • .NET 8 SDK、Visual Studio 2022、WinUI 3 / Windows App SDK 工作负载。
  • 目标框架为 net8.0-windows10.0.19041.0，桌面包类型为 WindowsPackageType=None。
  • 主要依赖包括 Windows App SDK 1.8、Win2D 与 CommunityToolkit.Mvvm 8.3.2。
  • 正式安装包内置 Python Worker；普通用户无需自行安装 Python。开发 Provider 时才需要项目的 Python 测试环境。

源码仓库可能包含尚未提交的开发改动。分析正式版行为时，应先核对 tag 或已提交版本，再依据对应版本的 CHANGELOG.md 与测试结果。

五、回归检查

Tests 目录使用独立控制台测试项目覆盖关键行为。按改动范围选择，涉及核心链路时建议全部运行：

  • ManifestUpdate.Tests：ACF 更新、候选沿用与备份规则。
  • SteamAppInfo.Tests：AppID 元数据解析与选择。
  • PlayTime.Tests：时长会话、迁移与合并。
  • HomeContentContract.Tests、HomeContentCache.Tests、HomeContentE2E.Tests：首页模型、缓存与端到端数据。
  • FastApiHomeContentService.Tests、PythonWorkerSpawner.Tests：本机 Worker 通信与生命周期。
  • BackgroundCrop.Tests、CustomNavigation.Tests、UpdateService.Tests：外观、导航与软件更新。

构建和测试成功不等于真实游戏一定可启动。Steam 覆盖、反作弊、管理员权限、官方启动器令牌和桥接进程生命周期仍需在真实环境中验证。

六、扩展新游戏

  1. 先收集真实启动链确认官方启动器、真实游戏进程、工作目录、必要参数与退出行为。
  2. 补充游戏来源配置在共享游戏来源字典中添加可识别的目录、EXE、AppID 与 Provider 信息，避免把规则写死在页面。
  3. 选择首页 Provider优先复用现有厂商 Provider；只有数据结构不同且无法配置时才新增实现。
  4. 保存完整启动字段确保真实 EXE、工作目录、参数和三种启动方式在克隆、载入、保存及脏状态比较中完整流转。
  5. 增加契约测试覆盖识别、Provider 映射、配置保存、启动参数和回退行为，再进行真实启动验证。
