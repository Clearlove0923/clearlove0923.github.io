一、这个项目在做什么（5 分钟版）

一句话：生成符合 Steam 格式的 appmanifest_*.acf（安装记录）文件，让 Steam 将已安装的国服游戏识别为库内条目，再通过 Steam 启动选项在点"开始"时运行国服游戏本体——从而使用 Steam 的截图覆盖层、时长记录、好友状态。

两层机制

层手段效果
文件层生成 ACF（StateFlags=4 = 已安装）Steam 库里出现游戏条目
进程层启动选项 "国服EXE" %command%点"开始"实际运行国服 exe

关键认知：这个软件不启动任何游戏。它是一个"配置生成器"，启动器角色始终由 Steam 承担。所有 Steam 功能（截图 / 时长 / 好友）零开发、自动生效，前提是游戏从 Steam 库启动。

启动链路

Program.Main (Program.cs:36)
  └─ Application.Start → new App()          (App.xaml.cs:20)
       └─ App.OnLaunched (App.xaml.cs:29)
            └─ MainWindow（导航 + 日志面板）
                 └─ 各功能页（鸣潮页 / 自定义页 / 设置页）
                      └─ 配置落盘：ACF + 占位 EXE + 启动命令
                           └─ 重启 Steam → 库中出现条目 → 点开始跑国服

为什么比传统做法好：传统做法需要完整下载国际服本体（约 60GB）来让 Steam 生成"真实 ACF"模板，再另装国服。本项目用 steamcmd.net 公开 API 在线查 buildid / manifest，手写 ACF + 空占位 EXE，国际服本体全程不存在——只留国服一份。

二、开发环境

  • Windows 10/11 x64 + .NET 8 SDK + Visual Studio 2022（勾选 WinUI 3 / Windows App SDK 工作负载）
  • 依赖（NuGet 自动还原）：Microsoft.WindowsAppSDK 1.8、CommunityToolkit.Mvvm 8.3.2、Microsoft.Win32.Registry
  • 目标框架：net8.0-windows10.0.19041.0，非 MSIX 打包（WindowsPackageType=None），入口由 DISABLE_XAML_GENERATED_MAIN 指定到 Program.Main
  • 打开 SteamCN-GameLauncher.sln，F5 即可调试；打包见 packaging/README.md（Inno Setup：SteamCN-GameLauncher.iss）

测试

断言式控制台程序，非 xUnit，每个都是一个行为契约：

dotnet run --project Tests/ManifestUpdate.Tests
dotnet run --project Tests/SteamAppInfo.Tests
dotnet run --project Tests/CustomNavigation.Tests
dotnet run --project Tests/BackgroundCrop.Tests

改 ACF 生成相关代码后，至少跑 ManifestUpdate.Tests 回归。

三、学习路线（按顺序执行）

阶段 0 · 前置认知（半天）

  • C# 基础 + XAML / WinUI 3 概念（页面、ContentDialog、NavigationView）
  • 最重要的一步：用文本编辑器打开自己电脑上 Steam\steamapps\ 下任意一个 appmanifest_*.acf，对照本项目的 GenerateAcfContent 输出看结构

阶段 1 · 数据模型（0.5 小时）

文件内容
Models/GameConfig.cs游戏预设（AppID / DepotID / 路径），鸣潮硬编码在 GameConfigs.All
Models/SteamAppInfo.cssteamcmd.net 返回的元数据模型
Models/AppSettings.cs全局设置（Steam 路径、SteamID 等）

阶段 2 · 核心服务（重点，2 小时）

按此顺序读 Services/SteamService.cs：

  1. DetectSteamInstallPath() — 注册表 + 常见路径找 Steam
  2. DetectSteamLibraryPaths() — 解析 libraryfolders.vdf
  3. DetectCnWutheringWavesPaths() — 三路找国服本体（官方注册表 / WeGame 注册表 / 全盘扫描）
  4. GenerateAcfContent()（约 L301，全项目灵魂） — 手写 ACF 模板；注意 StateFlags=4、路径 \\ 转义、SharedDepots 228989（Steamworks 运行库，不可删）
  5. EnsureGameDirAndPlaceholder()（L262）— 建占位目录和 0 字节 EXE，绝不覆盖真实文件
  6. GenerateLaunchCommand() — 生成 "国服EXE" %command%

然后读 Services/ManifestFileService.cs（很短）：WriteWithBackupAsync 的临时文件原子替换 + 滚动备份（每 AppID 最多 2 份 / 30 天）。

阶段 3 · 完整链路（1 小时）

精读 Views/Pages/WutheringWavesPage.xaml.cs：

  • Generate_Click（L222）— 从 UI 点击到 ACF 落盘的完整闭环，读懂这个方法主流程就通了
  • 获取元数据按钮处理（约 L190）→ FetchSteamDbInfoAsync
  • CopyCommand_Click（L312）— 生成 / 复制启动命令

阶段 4 · 工程化版本（1.5 小时）

CustomManifestPage（3 个分部文件）= 鸣潮页的泛化版：

  • CustomManifestPage.xaml.cs — 任意游戏配置 + 离开页面自动保存
  • CustomManifestPage.GameInfo.cs — AppID 自动填充（调 steamcmd.net，候选筛选、过期结果丢弃）
  • CustomManifestPage.OneClickUpdate.cs — 一键更新（重拉元数据重写 ACF，走带备份的 ManifestFileService）
  • Services/SteamAppSelectionService.cs — 多候选筛选策略

注意对比：鸣潮页直写 ACF（File.WriteAllTextAsync），自定义页走带备份的服务——项目正在从"专版"向"通用版"迁移。

阶段 5 · 外围与测试（按需）

  • SettingsService（JSON 持久化 + 锁内更新防覆盖）、LogService、UpdateService、AppearanceService / BackgroundCrop*
  • Tests/ 4 个测试项目 = 各服务的行为文档

自检标准

能不看代码回答：① ACF 里 StateFlags=4 是什么意思？② 占位 EXE 的作用？③ 启动命令 %command% 怎么工作？④ 为什么不需要下载国际服？⑤ 一键更新在更新什么？

四、二次开发路线（由小到大）

动手前

  • 新建 git 分支；备份 Steam steamapps 目录（改的是真实 Steam 文件）
  • 先跑一遍 4 个测试确认基线全绿

任务 1（入门）· 预设数据驱动化

GameConfigs.All 目前硬编码在代码里。把它挪到 JSON（随程序分发或放设置目录），UI 预设下拉框动态读取。涉及：Models/GameConfig.cs、鸣潮页 / 自定义页预设区、SettingsService。

任务 2（进阶）· 新增一个游戏的专用页

两条路：

  • 零代码：直接用 CustomManifestPage 的 AppID 自动填充，填好保存即可
  • 做专用页：复制 WutheringWavesPage.xaml(.cs) 改造——替换 GameConfig 常量、目录检测逻辑（参考 SteamService 里国服检测的三种手段），再在 MainWindow 注册导航项

任务 3（工程）· 多 Depot 支持

当前 ACF 只支持一个 Depot（InstalledDepots 单条）。某些游戏需要多个 Depot 共同生效。涉及：SteamService.GenerateAcfContent 的 AcfParameters、SteamAppSelectionService。改完跑 ManifestUpdate.Tests 回归。

任务 4（产品化）· 统一"游戏库" UI

把"逐页配置"改成卡片网格（GridView + GameConfig 数据源）：每张卡片显示游戏封面 / 名称，点击进配置或直接执行配置流程。这是向"统一启动中心"演进的自然方向。

任务 5（重构）· 轻量启动器路线（放弃 Steam 集成）

如果你想要的是"独立 UI + 点一下启动"（不依赖 Steam 的时长与社交功能）：

  • 砍掉：GenerateAcfContent、EnsureGameDirAndPlaceholder、ManifestFileService、SteamAppInfoService、CustomManifestPage
  • 保留：SteamService 的检测逻辑（注册表 + 全盘扫描，通用价值最高）、GameConfig、SettingsService、LogService、MainWindow 框架
  • 新增：Process.Start 启动 + 自己监听进程退出做时长统计（不再有 Steam 帮你记）

五、调试与排错

手段位置
UI 日志面板各页面底部（LogService）
启动早期日志%LOCALAPPDATA%\SteamCN-GameLauncher\logs\early-startup.log
启动崩溃日志%LOCALAPPDATA%\SteamCN-GameLauncher\logs\startup-crash.log（兜底：程序目录）
设置文件%APPDATA%\SteamCN-GameLauncher\settings.json
ACF 备份程序目录 backups\<AppID>\（最多 2 份 / 30 天）

常见问题：

  • Steam 库条目报"需要更新 / 校验失败" → manifest 过期，用一键更新重写 ACF
  • 改完没生效 → 重启 Steam（Steam 启动时才读 ACF）
  • 想回滚 → 从 backups\<AppID> 拷回原 ACF
